# BearGuardian - ソリューション提案書（ピッチ資料）

## 1. 解決したい課題

### ユーザーの生活スタイルに即した課題設定

**ターゲットユーザー**: 長野市に引越し予定のITエンジニア家族
- **夫（30代）**: 自宅でリモートワークに従事するITエンジニア
- **妻・子供**: 幼稚園の送迎や買い物などで日常的に外出する機会が多い
- **居住地**: 長野市内（新居付近で熊の目撃情報あり、徒歩4分の距離）

**心理的状況**:
- 「いつ熊が出るかわからない」という漠然とした恐怖感が強い
- 地理勘があるため、日常の行動範囲と危険エリアが重なることに敏感になっている
- 引越し初日から使える具体的な安全対策が必要

**課題の本質**:

1. **情報の非対称性**: 
   - 熊出没情報はPDFで公開されているが、リアルタイムで把握しにくい
   - 情報が構造化されておらず、地図上で直感的に理解できない

2. **家族の安全への不安**: 
   - 外出する家族の位置と危険エリアの関係が可視化されていない
   - 在宅の夫が家族の安全をリアルタイムで監視する手段がない

3. **在宅の夫の無力感**: 
   - リモートワーク中でも家族の安全を守りたいが、具体的な手段がない
   - 「何かあったらどうしよう」という不安を抱えながら仕事をしている

4. **予防的対策の欠如**: 
   - 危険エリアへの接近を事前に検知する仕組みがない
   - 回避ルートの提案など、実用的な情報提供がない

**解決すべき核心的課題**: 
**「在宅の夫が、外出する家族の安全をどう守るか」**という問いに対する、技術的かつ倫理的に納得できるソリューションの提供。

## 2. 課題の解決方法

### アプローチの詳細

BearGuardianは、**「情報の可視化とリアルタイム監視による予防的安全システム」**を提供します。熊を攻撃するのではなく、**「出会わないための回避」**を目的とした、共存を前提としたソリューションです。

### 解決アプローチの3つの柱

#### 柱1: 情報の構造化と可視化
- 長野市の熊出没情報PDFを自動解析し、構造化データ（JSON）に変換
- 地図上に目撃位置をマーカーで表示し、500m半径の危険エリアを視覚化
- 新居からの距離を自動計算し、リスクレベルを直感的に把握可能に

#### 柱2: リアルタイム監視システム
- 家族の位置情報をリアルタイムで地図上に表示
- WebSocketによる即座の通知機能
- 在宅の夫がダッシュボードで一元管理し、常に家族の安全を把握

#### 柱3: 予防的アプローチ
- 家族が危険エリア（500m以内）に近づいた際に自動通知
- 危険エリアへの接近を事前に検知し、回避行動を促す
- 将来的には安全なルート提案機能を実装可能な設計

### データフローとエンジニアリング

```
[長野市PDF] 
    ↓
[PDF解析ツール] → [構造化データ(JSON)] 
    ↓
[FastAPI バックエンド] 
    ↓                    ↓
[React Frontend]    [WebSocket]
    ↓                    ↓
[地図可視化]      [リアルタイム通知]
    ↓                    ↓
[家族位置情報] → [危険検知エンジン] → [通知表示]
```

**データの取得から可視化/通知までのフロー**:
1. **データ取得**: 長野市の熊出没情報PDFをダウンロード
2. **データ変換**: PDF解析ツールで構造化データ（JSON）に変換
3. **データ保存**: JSONファイルとして保存（将来的にDBへ移行可能）
4. **API提供**: FastAPIでRESTful APIとして提供
5. **リアルタイム通信**: WebSocketでリアルタイム更新を配信
6. **可視化**: React + Leafletで地図上に表示
7. **危険検知**: 家族の位置と熊出没エリアの距離を計算
8. **通知**: 500m以内に接近した場合、即座に通知を表示

### 動物愛護・共存の視点の実現

**重要な設計思想**: 熊を過度に傷つけたり、生態系に悪影響を与える攻撃的な手法（駆除・捕獲前提）は採用しない。

- **回避を目的**: 「出会わないための情報提供」に徹する
- **攻撃的でない**: 熊を傷つけたり、捕獲・駆除を前提としない
- **生態系への配慮**: 熊の生息地を避けて移動するルートを提案（将来拡張）
- **教育効果**: 情報を可視化することで、地域の熊の行動パターンを理解し、適切な距離感を保てる

## 3. 利用した技術スタック

### 選定理由の総括

エンジニアユーザーが「このアーキテクチャなら運用できる」「技術的に信頼でき、かつ倫理的にも納得できる」と思える技術スタックを選択しました。シンプルで標準的、かつ拡張性の高い構成を心がけています。

### バックエンド技術スタック

| 技術 | バージョン | 選定理由 |
|------|-----------|---------|
| **Python** | 3.11 | PDF解析ライブラリが豊富、データ処理に適している。エンジニアが慣れ親しんだ言語 |
| **FastAPI** | 0.104.1 | 高速、自動APIドキュメント生成、WebSocket対応。モダンで保守しやすい |
| **Uvicorn** | 0.24.0 | ASGIサーバー、非同期処理に対応。本番環境でも安定動作 |
| **pdfplumber** | 0.10.3 | PDFからのテキスト抽出に適している。長野市PDFの解析に使用 |
| **Pydantic** | 2.5.0 | データバリデーション、型安全性。APIの信頼性を担保 |

**選定のポイント**:
- PythonはPDF解析やデータ処理のエコシステムが充実しており、ETL処理が容易
- FastAPIは開発速度が速く、WebSocketの実装が容易。自動生成されるAPIドキュメントで運用が楽
- エンジニアユーザーが運用しやすいシンプルな構成

### フロントエンド技術スタック

| 技術 | バージョン | 選定理由 |
|------|-----------|---------|
| **React** | 18.2.0 | コンポーネントベース、豊富なエコシステム。モダンなUI開発に適している |
| **Leaflet** | 1.9.4 | 軽量、カスタマイズ性が高い地図ライブラリ。OpenStreetMap使用でAPIキー不要 |
| **react-leaflet** | 4.2.1 | ReactとLeafletの統合。Reactのコンポーネントとして地図を扱える |
| **WebSocket API** | ネイティブ | ブラウザ標準API。追加ライブラリ不要でリアルタイム通信を実現 |

**選定のポイント**:
- ReactはモダンなUI開発に適しており、コンポーネントの再利用性が高い
- LeafletはOpenStreetMapを使用でき、APIキー不要でコスト削減
- 軽量でカスタマイズしやすく、将来的な機能拡張に対応可能

### インフラ・デプロイ技術スタック

| 技術 | 選定理由 |
|------|---------|
| **Docker** | 環境の再現性、簡単なデプロイ。エンジニアが再現可能な手順を実現 |
| **Docker Compose** | 複数サービス（バックエンド・フロントエンド）の一元管理。起動が簡単 |
| **JSONファイル** | プロトタイプ段階でのシンプルなデータストレージ。将来的にDBへ移行可能 |

**選定のポイント**:
- Dockerにより環境構築が容易で、エンジニアユーザーが再現可能な手順を実現
- Docker Composeで`docker-compose up`一発で起動可能
- JSONファイルはプロトタイプ段階では十分。将来的にPostgreSQL等への移行が容易な設計

## 4. 実運用にあたって必要なランニングコスト

### 概算費用

エンジニアユーザーが個人レベルで運用可能なコストを想定しています。オープンソース技術を最大限活用し、最小限のコストで運用できる設計です。

### プロトタイプ段階（引越し初日から使用可能）

| 項目 | 費用 | 備考 |
|------|------|------|
| **サーバー（VPS/クラウド）** | 月額 500-1,000円 | 小規模VPS（1GB RAM、1コア）で十分。例: ConoHa VPS、さくらのVPS |
| **ドメイン** | 年額 1,000-2,000円 | オプション。IPアドレス直アクセスでも可 |
| **SSL証明書** | 無料 | Let's Encrypt使用（自動更新可能） |
| **地図タイル** | 無料 | OpenStreetMap使用（APIキー不要） |
| **データストレージ** | 無料 | JSONファイル（小容量） |
| **合計（月額）** | **約500-1,000円** | 個人利用レベルで十分運用可能 |

### 本格運用時の想定コスト

| 項目 | 月額費用 | 備考 |
|------|---------|------|
| **クラウドサーバー（AWS/GCP）** | 1,000-3,000円 | t3.micro / e2-micro（無料枠利用可能な場合も） |
| **データベース（オプション）** | 0-1,000円 | PostgreSQL（小規模、VPS内で運用可） |
| **CDN（オプション）** | 0-500円 | Cloudflare無料プラン利用可能 |
| **監視・ログ（オプション）** | 0-1,000円 | 無料プラン利用可能（例: Sentry、Logtail） |
| **バックアップ** | 0-500円 | VPSの自動バックアップ機能を使用 |
| **合計（月額）** | **約1,000-5,000円** | 運用規模と機能拡張による |

### コスト削減のポイント

1. **オープンソース技術の最大活用**: 
   - OpenStreetMap（地図タイル無料）
   - Let's Encrypt（SSL証明書無料）
   - オープンソースのライブラリを中心に構成

2. **小規模構成で開始**: 
   - プロトタイプ段階では最小構成（VPS 1台）で運用
   - 必要に応じて段階的に拡張

3. **スケーラブルな設計**: 
   - 将来的にデータベースやCDNを追加しても、既存コードの変更が最小限
   - マイクロサービス化も容易な設計

### 追加機能実装時のコスト

| 機能 | 追加コスト | 備考 |
|------|-----------|------|
| **スマートフォンアプリ** | 開発コスト（時間）のみ | Flutter/React Nativeで実装可能。既存APIを活用 |
| **プッシュ通知** | 無料枠あり | Firebase Cloud Messaging（無料枠: 月間無制限） |
| **ルート最適化** | 0-3,000円/月 | OpenRouteService（無料枠あり）またはGoogle Maps API（有料） |
| **SMS通知** | 1-5円/通 | Twilio等のSMSサービス（オプション） |

### コスト試算のまとめ

- **最小構成（プロトタイプ）**: 月額 **500-1,000円** で運用可能
- **標準構成（本格運用）**: 月額 **1,000-3,000円** で安定運用可能
- **拡張構成（機能追加）**: 月額 **3,000-5,000円** で高度な機能も利用可能

**結論**: 個人レベルの運用であれば、月額1,000円程度で十分に運用可能な設計となっています。

## まとめ

BearGuardianは、**「技術で家族を守る」**という目的を、**「共存の視点」**を大切にしながら実現するソリューションです。

### 核心的な価値

**恐怖を安心に変える**: 情報の可視化とリアルタイム監視により、在宅の夫が外出する家族の安全を守ることができます。

### エンジニアとしての信頼性

- **シンプルなアーキテクチャ**: 複雑な依存関係を避け、運用しやすい構成
- **標準技術の使用**: 広く使われている技術スタックで、情報が豊富
- **再現可能な手順**: Docker Composeで`docker-compose up`一発で起動可能
- **拡張性**: 将来的な機能追加に対応できる設計

### 倫理的配慮

- **動物愛護**: 熊を傷つけず、共存を前提とした設計
- **プライバシー**: 位置情報は家族内でのみ共有
- **情報の正確性**: 公式情報（長野市PDF）を基にしたデータ提供

### 引越し初日から使える

- **簡単なセットアップ**: Docker Composeで数分で起動可能
- **モックデータ付き**: すぐに動作確認が可能
- **実データ対応**: PDF解析ツールで実データにも対応可能

**このアーキテクチャなら運用できる。技術的に信頼でき、かつ倫理的にも納得できる。**
